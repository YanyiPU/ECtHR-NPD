# ECtHR-NPD agent controller

This package contains controller source, legal/policy modules and schemas. The single current public dataset is at `../data/`: 14,575 cases with fixed splits and readable fields. No private release contract or encoded feature matrix is required. See [EXPERIMENTS.md](../docs/EXPERIMENTS.md) for preparation, prior construction and an offline controller command.

Run `code/prepare_experiments.py prepare` from the package root to create `train_cases.csv`, `train_targets.csv` and `agent_cases.jsonl` outside the dataset package. Build a fresh empirical-prior directory with those training files and `--dataset-release .`. The builder verifies the exact public training IDs, dates, countries, Articles and amounts; the resulting manifest binds their hashes and the four generated prior tables. Neither validation nor test labels contribute. Label-source counts remain unavailable because the public dataset has no historical `y_source` ledger.

`react_orchestrator.py` uses `strict_react` by default. With `--paper_preset`, it exposes the bounded Table 24/25 action protocol, maximum 12 steps and at most five retrieved references. Its target packet contains only the strict prepared serialization, safe metadata and permitted merits/facts hints. Identifier/date fields support joins and retrieval; targets, beneficiary allocations, claim state, Article 41 reasoning, operative clauses and zero rationales are excluded. The leakage check runs before final scoring.

References are training-only, strictly earlier than the target date, exclude the target itself and share at least one violated Article. Empirical priors fall back from article-country to article, country and global article-weighted estimates. Whitelisted actions expose allowed case information, knowledge modules, reference retrieval and priors; the model never reads arbitrary files.

A dry run writes an implementation trace without model calls or a scored prediction. Structured public-table dry runs do not reproduce raw-text historical ReAct results. A live run uses the shipped compatible client and requires an explicit model, provider endpoint and credentials, with provider snapshot/access-date/decoding information recorded by the researcher. `ECTHR_NPD_OPENAI_COMPATIBLE_CLIENT` remains an optional custom client module override. Historical requests, model snapshots, predictions and traces are unavailable.

Expanded modes require `--allow_restricted_diagnostic` and separate authorized inputs. They are not the common benchmark-input condition. `orchestrator_v2.py` is retained for shared helper imports and a guarded legacy diagnostic interface. The public commands use `react_orchestrator.py`.
